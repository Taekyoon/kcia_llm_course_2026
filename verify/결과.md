### 3-3. 🟢 klue/klue ner 라벨 스킴 — **NER 재작성이 예상보다 쉽습니다**

```python
{'sentence': Value('string'),
 'tokens':   List(Value('string')),
 'ner_tags': List(ClassLabel(names=[
     'B-DT','I-DT','B-LC','I-LC','B-OG','I-OG',
     'B-PS','I-PS','B-QT','I-QT','B-TI','I-TI','O']))}
```

**컬럼명이 `tokens` / `ner_tags` 로 기존 `kor_ner` 와 동일**합니다.
따라서 `align_labels_with_tokens`, `tokenize_and_align_labels` 함수는 **거의 그대로 재사용 가능**합니다.

라벨은 13종 (6개 개체 유형 × B/I + O):
`DT`(날짜) · `LC`(지역) · `OG`(기관) · `PS`(인물) · `QT`(수량) · `TI`(시간)

⚠️ 확인 필요: `ner_tags` 타입이 `Sequence` → **`List`** 로 바뀌었습니다(datasets 5.x).
NER 노트북 셀 11-12 의 `dataset["train"].features["ner_tags"].feature.names` 접근이 여전히 유효한지 실행 확인이 필요합니다.

## 8. 마이그레이션 수정본 검증 [확정] — 2026-08-25

`work/notebook/` 수정본 기준. **13개 점검 중 12개 통과, 1개 실패 → 대체안 확인.**

### 8-1. ★ mmBERT-base 한국어 성능 — **경계선 통과**

유일하게 남아 있던 모델 선정 리스크입니다.

```
NSMC 정확도 0.8545  (eval_loss 0.4186)
조건: 학습 8,000행 / 500스텝 / max_length=128 / 36초
```

**판정: 사용 가능. 단 여유는 없습니다.**

- 사전에 세운 기준 **0.85 이상**을 통과했습니다 (0.8545)
- 다만 **이 측정은 의도적으로 작게 잡았습니다.** NSMC 전체는 15만 행인데 8천 행만,
  500스텝만 돌렸습니다. 비교 대상으로 언급한 "네이티브 0.88~0.90"은 **전체 파인튜닝**
  수치라 직접 비교가 아닙니다. 0.8545는 **하한**으로 봐야 합니다
- 학습 손실이 0.49→0.15로 계속 떨어지는 중이었고, eval_loss(0.42) > train_loss(0.15)라
  8천 행 부분집합에 과적합이 시작된 상태였습니다. 데이터를 늘리면 개선됩니다

**⚠️ 한국어 토큰화 효율은 확실히 나쁩니다** (다국어 모델의 대가):

```
'안녕하세요, 반갑습니다.' → ' 안','녕','하세요',',',' 반','갑','습니다','.'
'홍길동은 서울에 산다'   → ' 홍','길','동','은',' 서울','에',' 산','다'
```

거의 음절 단위로 쪼개집니다. 시퀀스가 길어져 연산이 늘고, **특히 NER 은 토큰 경계가
성능에 직결**되므로 분류보다 영향을 크게 받을 수 있습니다.

→ **NER 실습의 실제 F1 측정이 추가로 필요합니다.** 분류(0.8545)만으로 판단하기엔 이릅니다.

### 11-0. 📌 실습 시간 배분에 쓸 수 있는 실측치

### 11-1. Amazon 요약 완주 — 가장 걱정하던 구간

이 노트북이 가장 취약했습니다:
- 7단계가 **사슬**로 엮임 (Step1 출력 → Step3 입력, Step2 → `json.loads()` → Step6)
- `.beta.chat.completions.parse()` → `.create()` 로 **6곳 변경, 실행 검증 없음**
- 모델이 JSON 을 코드펜스로 감싸면 `json.loads()` 가 깨질 위험

**전부 통과했습니다.** `response_format` 이 순수 JSON 을 반환해 코드펜스 문제도 없었습니다.

### 11-2. ⚠️ "완주"가 "정상 동작"이 아닙니다

이 노트북의 각 스텝은 이렇게 생겼습니다:

```python
def gen_text_step_1(text):
    try:
        ...
        return completion.choices[0].message.content
    except Exception as e:
        print(e)
        return 'error'
```

**예외를 삼키고 `'error'` 문자열을 반환한 뒤 계속 진행합니다.**
모든 LLM 호출이 실패해도 노트북은 "완주"로 끝납니다.

→ 실행 결과 노트북에서 `'error'` 출현 횟수와 최종 산출물(`amazon_gpt_summary.csv`)을
**별도로 확인해야 합니다.** 완주 여부만으로 판단하면 안 됩니다.

> 이 `try/except` 는 원본부터 있던 구조입니다. 실습 중 한 스텝이 실패해도 진행되도록
> 한 의도로 보이나, **실패가 조용히 묻히는** 부작용이 있습니다.
> 개선 계획에 넣을지 검토가 필요합니다.

### 11-3. 도달 과정 — 실행해봐야만 나온 문제들

9종 통과까지 **세 차례** 실패를 거쳤습니다. 전부 정적 분석·웹 조사로는 못 잡는 것이었습니다.

| 차수 | 실패 | 원인 |
|---|---|---|
| 1차 | 6종 | `matplotlib` 미설치 · `overwrite_output_dir` 제거 · `GRPOConfig.max_prompt_length` 제거 |
| 2차 | 6종 | **vLLM 이 GPU 선점해 학습계 OOM** · `apply_chat_template` 반환형 변경 · `SubQuestionQueryEngine` 패키지 |
| 3차 | 0종 | `llama-index-question-gen-openai` 가 core 를 다운그레이드 · `openai` 버전 상한 |

**특히 값진 것 셋:**

1. **`overwrite_output_dir`** — CLAUDE.md 에 "어느 노트북에서도 쓰이지 않는다"고 **단정해뒀는데 틀렸습니다.** SFT·DPO 두 곳에 실재했습니다. 검증 없이 적은 것이고, 돌려보지 않았으면 강의 당일 학습 직전 셀에서 터졌을 문제입니다.

3. **`llama-index-question-gen-openai`** — 라이브러리가 에러 메시지로 **직접 설치를 권하는데 그게 함정**이었습니다. core 를 0.14 → 0.12 로 끌어내려 llama-index 전체를 깹니다. 설치 전에 핀을 확인했어야 했습니다.

### 11-6. 🔴 새로 발견 — SubQuestionQueryEngine 이 서브질문을 영어로 만든다

셀 31 출력:

```
Generated 1 sub questions.
[wiki_docs] Q: What is Maxwell's equation?          ← 한국어 질의가 영어로 바뀜
[wiki_docs] A: 주어진 컨텍스트는 맥스웰 방정식에 대한 내용을 포함하지 않으며,
              칼 세이건과의 관련, 공생, 진화생물학 등 ...    ← 엉뚱한 문서
```

**원인**: `question_gen:question_gen_prompt` 가 영어이고 few-shot 예시도 Uber/Lyft
재무제표입니다. 그래서 한국어 질의를 영어 서브질문으로 바꿔버립니다.

**왜 치명적인가**: BM25 는 **어휘를 그대로 매칭**하는 검색입니다.
영어로 물으면 한국어 위키에서 아무것도 못 찾고 엉뚱한 문서가 걸립니다.
임베딩 검색이었다면 언어가 달라도 어느 정도 찾았을 텐데, BM25 라 정면으로 실패합니다.

셀 30(백남준)은 **우연히** 서브질문이 한국어로 나와서 됐습니다. 재현성이 없습니다.

**조치**: `question_gen_prompt` 도 한국어로 교체했습니다.
refine_template 을 바꿨던 것과 같은 패턴이라 실습 흐름상으로도 자연스럽고,
**"프롬프트는 하나만 바꿔서 되는 게 아니다"** 는 점을 보여주는 교보재가 됩니다.

> 이것도 "완주했다" 로는 절대 안 잡히는 문제였습니다. 셀은 전부 에러 없이 돌았고
> 답변도 그럴듯하게 나왔습니다. **출력을 읽어봐야만** 보입니다.

### 11-4. MiniGPT — 학습량이 부족하면 완주해도 소용없다

첫 실행에서 **22초 만에 완주**했습니다. 완주는 했지만 학습이 5.3초라 결과가 이랬습니다:

> Greedy: `"엄마, "엄마, "엄마, "엄마, ...`

데이터를 40배 늘린 뒤(2만 → 15만 문서, 1 → 3 에폭):

```
Perplexity 176.98 → 18.92
Greedy: 하지만, 뜻밖의 일이 벌어졌어요. 큰 바람이 불어서 팀의 모자를 날려버렸죠.
        팀은 슬퍼했지만, 그때, 친절한 새가 날아와 팀의 모자를 낚아채 갔어요...
```

**"완주했다"는 신호가 얼마나 무의미할 수 있는지** 보여주는 사례입니다.

### 10-1. 🔴 `guided_json`/`guided_choice` 는 **에러가 아니라 조용히 무시**됩니다

앞서 D-2 에 "v0.12 에서 제거 → 실패"로 적었습니다. **틀렸습니다.**

| 호출 | 결과 |
|---|---|
| `extra_body={"guided_choice": ["긍정","부정"]}` | ❗ 에러 없음. **장문 에세이 반환** (선택지 무시) |

수강생이 *"모델이 형식을 잘 못 지키네"* 로 오해하고 넘어갑니다.
LlamaIndex `get_prompts()` 건(D-3)과 **정확히 같은 실패 유형**입니다 — 조용한 오작동.

→ 퓨샷 3곳 + 퓨샷 2곳 + Amazon 6곳, 총 **11곳이 조용히 망가진 상태**였습니다.
→ 마이그레이션의 정당성이 오히려 강해졌습니다.

## 9. 인코더 모델 비교 [확정] — 2026-08-25

`verify/04_인코더비교.py`. 동일 조건(seed 42 · lr 3e-5 · 동일 데이터·스텝).

| 모델 | 라이선스 | **NER F1** | NSMC acc | 토큰수 | 파라미터 |
|---|---|---:|---:|---:|---:|

| `monologg/koelectra-base-v3-discriminator` | Apache-2.0 | 0.6734 | **0.8710** | 50 | ~110M |

**결론: `mmBERT-base` 유지 확정.** NER F1 차이 **+0.2115**.

### 9-1. ⚠️ 사전 우려가 틀렸습니다

검증 전 이렇게 적었습니다:

> "한국어 토큰화가 거의 음절 단위다. **NER 은 토큰 경계가 성능에 직결되므로
> 분류보다 타격이 클 수 있다.**"

**정반대였습니다.** mmBERT 는 NER 에서 오히려 **크게 앞섰고**(0.885 vs 0.673),
근소하게 뒤진 쪽은 분류였습니다(0.853 vs 0.871).

한국어는 교착어라 개체명 경계가 어절 내부에 걸리는 경우가 많습니다.
`홍길동은` 에서 `홍길동` 과 `은` 을 갈라야 하는데, **음절 단위로 잘게 쪼개는 것이
오히려 경계를 잡는 데 유리**하게 작용한 것으로 보입니다.

토큰화 효율(1.32배)은 **연산 비용의 문제이지 성능의 문제가 아니었습니다.**

### 9-2. 다만 이 비교는 체급이 다릅니다 — 정직하게 기록

| | mmBERT-base | KoELECTRA-v3-base |
|---|---|---|
| 파라미터 | **307M** | ~110M (약 1/3) |
| 아키텍처 | ModernBERT (2024~25) | ELECTRA (2020) |
| 600스텝 시점 학습 손실 | 0.049 (수렴 근접) | **0.203 (아직 급강하 중)** |

KoELECTRA 는 **명백히 미수렴 상태**입니다(0.58→0.26→0.20). 스텝을 늘리면 상당히
올라갈 것이므로 **0.2115 라는 격차는 실제 품질 차이를 과장합니다.**

그럼에도 결론은 유지합니다:
- 3배 큰 모델이라도 **307M 은 여전히 실습에 가볍습니다** (NER 학습 45초)
- **적은 스텝에서 빨리 수렴하는 것은 실습에서 오히려 장점**입니다
- NSMC 열세(-0.0185)는 작고, NER 우세(+0.2115)는 큽니다
- **MIT 라이선스**라는 원래 채택 사유가 그대로 유효합니다

### 9-3. 절대 수준도 충분합니다

`mmBERT` 의 **NER F1 0.885 / accuracy 0.967** 은 8,000행·600스텝(45초)만으로 낸 값입니다.
교육용 실습으로 부족함이 없고, 수강생이 "실제로 되는구나"를 확인하기에 충분합니다.
