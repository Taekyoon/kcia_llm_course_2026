### 3-3. 🟢 klue/klue ner 라벨 스킴 — **NER 재작성이 예상보다 쉽습니다**

```python
{'sentence': Value('string'),
 'tokens':   List(Value('string')),
 'ner_tags': List(ClassLabel(names=[
     'B-DT','I-DT','B-LC','I-LC','B-OG','I-OG',
     'B-PS','I-PS','B-QT','I-QT','B-TI','I-TI','O']))}
```

**컬럼명이 `tokens` / `ner_tags` 로 기존 `kor_ner` 와 동일**합니다.
따라서 `align_labels_with_tokens`, `tokenize_and_align_labels` 함수는 **거의 그대로 재사용 가능**합니다.

라벨은 13종 (6개 개체 유형 × B/I + O):
`DT`(날짜) · `LC`(지역) · `OG`(기관) · `PS`(인물) · `QT`(수량) · `TI`(시간)

⚠️ 확인 필요: `ner_tags` 타입이 `Sequence` → **`List`** 로 바뀌었습니다(datasets 5.x).
NER 노트북 셀 11-12 의 `dataset["train"].features["ner_tags"].feature.names` 접근이 여전히 유효한지 실행 확인이 필요합니다.

## 8. 마이그레이션 수정본 검증 [확정] — 2026-08-25

`work/notebook/` 수정본 기준. **13개 점검 중 12개 통과, 1개 실패 → 대체안 확인.**

### 8-1. ★ mmBERT-base 한국어 성능 — **경계선 통과**

유일하게 남아 있던 모델 선정 리스크입니다.

```
NSMC 정확도 0.8545  (eval_loss 0.4186)
조건: 학습 8,000행 / 500스텝 / max_length=128 / 36초
```

**판정: 사용 가능. 단 여유는 없습니다.**

- 사전에 세운 기준 **0.85 이상**을 통과했습니다 (0.8545)
- 다만 **이 측정은 의도적으로 작게 잡았습니다.** NSMC 전체는 15만 행인데 8천 행만,
  500스텝만 돌렸습니다. 비교 대상으로 언급한 "네이티브 0.88~0.90"은 **전체 파인튜닝**
  수치라 직접 비교가 아닙니다. 0.8545는 **하한**으로 봐야 합니다
- 학습 손실이 0.49→0.15로 계속 떨어지는 중이었고, eval_loss(0.42) > train_loss(0.15)라
  8천 행 부분집합에 과적합이 시작된 상태였습니다. 데이터를 늘리면 개선됩니다

**⚠️ 한국어 토큰화 효율은 확실히 나쁩니다** (다국어 모델의 대가):

```
'안녕하세요, 반갑습니다.' → ' 안','녕','하세요',',',' 반','갑','습니다','.'
'홍길동은 서울에 산다'   → ' 홍','길','동','은',' 서울','에',' 산','다'
```

거의 음절 단위로 쪼개집니다. 시퀀스가 길어져 연산이 늘고, **특히 NER 은 토큰 경계가
성능에 직결**되므로 분류보다 영향을 크게 받을 수 있습니다.

→ **NER 실습의 실제 F1 측정이 추가로 필요합니다.** 분류(0.8545)만으로 판단하기엔 이릅니다.

### 9-1. ⚠️ 사전 우려가 틀렸습니다

검증 전 이렇게 적었습니다:

> "한국어 토큰화가 거의 음절 단위다. **NER 은 토큰 경계가 성능에 직결되므로
> 분류보다 타격이 클 수 있다.**"

**정반대였습니다.** mmBERT 는 NER 에서 오히려 **크게 앞섰고**(0.885 vs 0.673),
근소하게 뒤진 쪽은 분류였습니다(0.853 vs 0.871).

한국어는 교착어라 개체명 경계가 어절 내부에 걸리는 경우가 많습니다.
`홍길동은` 에서 `홍길동` 과 `은` 을 갈라야 하는데, **음절 단위로 잘게 쪼개는 것이
오히려 경계를 잡는 데 유리**하게 작용한 것으로 보입니다.

토큰화 효율(1.32배)은 **연산 비용의 문제이지 성능의 문제가 아니었습니다.**

### 9-2. 다만 이 비교는 체급이 다릅니다 — 정직하게 기록

| | mmBERT-base | KoELECTRA-v3-base |
|---|---|---|
| 파라미터 | **307M** | ~110M (약 1/3) |
| 아키텍처 | ModernBERT (2024~25) | ELECTRA (2020) |
| 600스텝 시점 학습 손실 | 0.049 (수렴 근접) | **0.203 (아직 급강하 중)** |

KoELECTRA 는 **명백히 미수렴 상태**입니다(0.58→0.26→0.20). 스텝을 늘리면 상당히
올라갈 것이므로 **0.2115 라는 격차는 실제 품질 차이를 과장합니다.**

그럼에도 결론은 유지합니다:
- 3배 큰 모델이라도 **307M 은 여전히 실습에 가볍습니다** (NER 학습 45초)
- **적은 스텝에서 빨리 수렴하는 것은 실습에서 오히려 장점**입니다
- NSMC 열세(-0.0185)는 작고, NER 우세(+0.2115)는 큽니다
- **MIT 라이선스**라는 원래 채택 사유가 그대로 유효합니다

### 9-3. 절대 수준도 충분합니다

`mmBERT` 의 **NER F1 0.885 / accuracy 0.967** 은 8,000행·600스텝(45초)만으로 낸 값입니다.
교육용 실습으로 부족함이 없고, 수강생이 "실제로 되는구나"를 확인하기에 충분합니다.
